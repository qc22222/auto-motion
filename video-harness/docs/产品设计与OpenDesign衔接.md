# 产品设计与 OpenDesign 衔接

## 结论

字幕环节可以高度流水化，而且克隆音色 TTS 正是把整条链路闭合的关键：确认文案同时成为配音文本、字幕文本和镜头语义来源；TTS 返回或对齐出的字词时间戳，再成为字幕和 Storyboard 时长的共同时间轴。

但“完全自动化”应理解为生产动作自动完成，而不是取消质量控制。真实成片仍应保留三个可见检查点：文案是否确认、分镜是否合理、最终试听/观看是否通过。

## 自动化后仍需人工可控的细节

- 多音字、英文缩写、品牌名和数字读法。
- 重音、停顿、情绪和语速是否符合本人习惯。
- 字幕是否需要语义换行，而不是只按字数切分。
- 某条字幕是否要提前、延后、隐藏或改变位置。
- 某个场景是否需要保留更长的落点和转场时间。
- 视觉生成是否偏离已经确认的层级、构图或品牌规范。

当前内核分别用 `voice-profile.json`、`caption-overrides.json`、`storyboard.json`、`shot-plan.json` 和结构化批注解决这些问题。

## 为什么先做内核，再做 OpenDesign

如果先做界面，界面很容易变成另一个黑箱：按钮很多，但底层没有明确的输入、输出、失效规则和审批语义。现在先固定本地产品协议，OpenDesign 只需要读写这些 JSON，并调用稳定命令。

```text
OpenDesign 界面
   ↓ 读写 JSON / 发起明确操作
本地服务层（字段修改、审批、推进、单镜头生成与任务轮询已完成）
   ↓ 调用
Video Harness CLI 与状态机（当前已完成）
   ↓ 适配
TTS / HyperFrames / FFmpeg / 场景生成工具
```

## 建议的前端信息架构

### 1. 项目总览

- 显示所有阶段和审批状态。
- 显示哪些文件因上游修改而过期。
- 一键进入当前真正需要处理的下一步。

### 2. 文案与音色

- 左侧逐段文案，右侧音色、语速、情绪、发音词典。
- 单段试听与重新生成，不必重做整条旁白。
- 波形上直接拖动停顿和段落边界。

### 3. Storyboard 时间线

- 每个场景是一张卡片和一段真实时长区间。
- 可拖动排序、修改场景归属、补充停留时间和转场。
- 修改后只使受影响的场景及下游交付失效。

### 4. 场景精修

- 中央预览，右侧编辑 `shot-plan.json` 和 `scene.config.json` 的友好表单。
- 可调整画面文字、素材、构图说明、动效强度和安全区。
- “只重做当前场景”是一级操作，而不是隐藏高级功能。

### 5. 字幕编辑器

- 波形、字幕块和视频预览同步。
- 直接改文字、起止时间、位置、字号、背景和隐藏状态。
- 全局样式写入 `design.json`，单条例外写入 `caption-overrides.json`。

### 6. 审阅与交付

- 场景级批注，自动落到 `reviews/revisions.json`。
- 对比返工前后版本。
- 最终批准后才允许正式渲染与交付。

## 前端实现边界

建议 OpenDesign 只负责交互和展示，不直接持有 TTS、FFmpeg 或 HyperFrames 的业务逻辑。当前 Harness 已增加只绑定 `127.0.0.1` 的薄服务，提供修改目录、影响预览、确认应用、状态读取、生产音频预检、审批、流水线推进、局部意见、单镜头生成、任务轮询、静态审阅和视频 Range 流；后续继续扩展同一个服务层：

- 读取和校验项目 JSON。
- 订阅 `.harness/state.json` 与运行日志。
- 把现有 job 轮询升级为事件流，并推送阶段/子进程进度。
- 提供本地预览文件和视频流。
- 增加真正可终止子进程树的取消、显式重试和持久化任务记录。

修改协议已经固定为 `target + id + changes`，并要求两步提交：先获取带源文件哈希的影响预览，再携带该预览指纹应用。OpenDesign 应消费服务返回的字段定义、范围和选项，不要自行猜测不同阶段的参数，也不要在前端复制失效图。

这样即使未来更换前端、TTS 服务商或视频引擎，项目数据和工作流仍然可用。

## 音色安全

- 只克隆本人或已明确授权的声音。
- 原始音色样本、`voiceId` 和凭据均应留在项目本地或服务商安全存储中。
- `.env` 已默认排除，不把密钥写入日志、JSON 或交付目录。
- 重要账号建议开启用量限制和密钥轮换。

## 前端启动条件

当前内核完成以下验收后即可开始 OpenDesign：

1. 用户可用真实克隆音色生成一条完整旁白。
2. 字词时间戳、字幕和 Storyboard 时长与试听一致。
3. 至少完成一次字幕单条精修和单场景局部返工。
4. 最终成片的音频、字幕、分辨率和时长验证通过。

## 2026-08-03 工程审计后的接入约束

- 当前 OpenDesign 页面中的阶段、字幕、批注和交付信息仍是硬编码原型数据，不能作为项目状态来源。
- 当前本地服务已暴露编辑目录、影响预览、确认应用、状态读取、音频预检、`advance`、三个 `approve`、`comment`、单场景 `generate` 和 job 查询；OpenDesign 应直接消费这些协议，不要在前端重新实现状态机。
- 分环节修改已覆盖项目意图/画布、旁白、音色、分镜、全局设计、单镜头画面、字幕、声音混合/交付。字段级影响矩阵是唯一失效依据；例如普通分镜只返工目标镜头，而 `extraHold` 还需重建音频静音段和字幕时间轴。
- `advance` 是推荐的流水线续接入口：自动阶段继续运行，遇到质量门返回 `waiting_approval`；前端显示真实阻塞原因并提供对应批准操作。
- UI 必须显著区分模拟音频与真实 TTS。`audio_meta.json.mock === true` 时不得显示“真实配音已完成”或允许无提示生产交付。
- 场景预览可以使用黑箱生成器预渲染的 MP4；最终批准后仍由 Harness 校验源文件哈希、渲染规格和交付状态。
- 真实克隆音色尚未在当前机器完成验收，因此服务层接入不能把桩测试或静音 WAV 当作 TTS 已上线的证据。
