# 用户验收清单

## A. 环境与本地化

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:/自媒体/视频制作/tools/video-harness.ps1" doctor
```

验收点：

- 必需项全部为 `✓`。
- 输出明确显示“仅项目本地，不使用全局安装”。
- 未配置真实 TTS 凭据时只提示未检测到，不会自动改用未知公共音色。

## B. 无凭据端到端

对一个新项目执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:/自媒体/视频制作/tools/video-harness.ps1" run `
  "<项目目录>" --mock --auto-approve
```

验收点：

- `delivery/final.mp4` 可播放。
- 成片有音频轨，字幕已烧录并同时保留 SRT/VTT。
- `validate --mock-audio` 通过。
- `status` 中 `delivery` 为已完成。

## C. 字幕精修

1. 打开 `captions/captions.json`，选择一个字幕 id。
2. 执行 `caption-set` 修改文字、时间或位置。
3. 重新执行 `captions`。

验收点：

- 只使字幕、审阅、渲染和交付过期。
- 修改后的 SRT/VTT 和字幕 HTML 同步变化。
- 重新生成音频不是必需步骤。

## D. 单场景返工

1. 对 `scene-002` 添加一条批注。
2. 执行 `revise --scene scene-002`。
3. 只修改该场景并执行 `build --scene scene-002 --accept`。

验收点：

- 只有 `scene-002` 进入待返工状态。
- 其他场景保持完成，字幕保持有效。
- 审阅页重新生成后可再次批准。

## E. 真实克隆音色

1. 在 `voice-profile.json` 填写本人克隆音色的服务商和 `voiceId`。
2. 把凭据写入该项目 `.env`。
3. 执行 `audio-check`，确认凭据、音色和时间戳/对齐能力全部通过。
4. 依次执行 `compile`、批准 `script`、执行 `audio`。

验收点：

- 每段 WAV 与完整 `narration.wav` 均可播放。
- `audio_meta.json` 中每段有 `words`、`duration_s`、`scene_offset_s`。
- Storyboard 场景时长与真实音频一致。
- 多音字、英文和数字读法可通过发音表或文本精修解决。
- BGM 模式不是 `none` 时，必须等 `bgm_pending` 变为 `false` 且音乐文件可探测后，音频阶段才允许完成。

## F. 最终通过标准

- 文案是唯一事实来源，没有 ASR 反向改写文案。
- 所有重要阶段有明确输入、输出和审批状态。
- 字幕可逐条精修。
- 场景可独立返工和重渲染。
- 成片通过时长、分辨率、视频流和音频流验证。
- 所有缓存和配置仍位于当前项目，没有新增全局技能或全局依赖。

## G. 黑箱生成桥接与断点续接

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:/自媒体/视频制作/tools/video-harness.ps1" advance "<项目目录>"
```

验收点：

- 命令只在 `script`、`storyboard`、`review` 三个质量门暂停，批准后可重复运行并从当前状态继续。
- 场景按顺序调用外部生成器，每个场景保留独立 stdout、stderr 和 Claude 原始流日志。
- 默认生成器读取现有 `auto-motion`/HyperFrames 共享技能，不复制或替换其视觉创作逻辑。
- 场景任务单能从场景目录正确读取 `../../BRIEF.md`、`../../frame.md`、`../../STORYBOARD.md` 和本目录 JSON。
- 真实 TTS 的旁白音轨会补齐场景停留与无旁白区段，最终时长与 Storyboard 一致。
- 修改多个场景后只重渲染其中一个时，全局 render 状态保持“可执行”，不会因旧 MP4 仍存在而误报完成。

当前尚未完成的生产验收：必须使用本人授权的真实克隆音色跑通一次；现有演示中的 `audio_meta.json` 明确标记为 `mock: true`。

## H. 审阅页分环节修改

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:/自媒体/视频制作/tools/video-harness.ps1" review "<项目目录>"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:/自媒体/视频制作/tools/video-harness.ps1" serve "<项目目录>" --port 4173
```

打开 `http://127.0.0.1:4173/reviews/index.html` 后逐项验收：

- 审阅页顶部能进入旁白、音色、设计和交付修改；场景卡片能分别进入分镜和画面修改；字幕旁有逐条修改入口。
- 文案、音色、分镜、设计、单镜头、字幕和交付看到的是各自参数，不出现通用 JSON 文本框。
- 修改按钮初始不可用；只有“预览影响”成功后才可确认应用。
- 旁白文本预览显示音频及完整下游过期，并撤销文案、分镜、审阅审批。
- 普通分镜或画面修改只使选中镜头过期；其他镜头与字幕保持完成。
- `extraHold` 修改明确提示音频与字幕也会过期。
- 单条字幕修改不使音频和镜头过期；重新执行 `captions` 后 SRT/VTT/ASS 同步更新。
- 预览后从另一个窗口改动同一事实来源，再点击应用时会提示“预览已过期”。
- 服务只监听 `127.0.0.1`；缺少同源请求头的修改请求返回 403。
- 顶部能看到全部阶段和当前质量门；推进动作返回后台任务并持续显示状态。
- 只有三个质量门能批准，批准动作不改参数；任务运行时再次修改、批注或生成会返回 409。
- 单镜头环节能执行“生成或返工当前镜头”，也能提交只影响该镜头的局部意见。
- 音色与交付环节能显示生产音频预检；缺少 HeyGen 凭据和 `voiceId` 时明确显示未就绪。
